# Fix Safe Area Handling for Overlay UI

## What
The compass and action buttons use hardcoded padding that doesn't account for Dynamic Island, notch, or home indicator. User reports the compass overlap issue is still not resolved from UR-002/REQ-011.

## Detailed Requirements

### Action buttons (top-right: stray/stats/gear)
- Currently: `.padding(.trailing, 16)` and `.padding(.top, 8)` — no safe area awareness
- Fix: Use `.safeAreaInset()` or ensure the VStack respects safe area insets despite MapView using `.ignoresSafeArea()`
- Must not be obscured by Dynamic Island on iPhone 14 Pro+ or notch on older iPhones

### Compass (bottom-left, during Stray session)
- Currently: `.padding(.bottom, 60)` — hardcoded, not safe-area-aware
- Fix: Use geometry reader or safe area insets to position above the home indicator
- Must not overlap with action buttons on any device size

### Session HUD (top-left, during Stray session)
- Verify it doesn't overlap with the status bar or Dynamic Island

### General
- The root issue: `MapViewRepresentable` uses `.ignoresSafeArea()` to make the map full-screen, but the overlay VStack then loses safe area context
- Solution approach: Either use `.safeAreaInset()` modifiers on individual elements, or wrap the overlay in a container that respects safe areas while the map underneath ignores them
- Test mentally on: iPhone SE (no notch), iPhone 14 (notch), iPhone 14 Pro (Dynamic Island), iPhone 15 (Dynamic Island)

## Context
- All layout in `Stray/Views/ContentView.swift` (lines 14-74)
- User flagged this in UR-002/REQ-011 and reports it's still not resolved
- The compass is `StrayCompassView` at `Stray/Views/StrayCompassView.swift`
- Map is `MapViewRepresentable` at `Stray/Views/MapViewRepresentable.swift`
